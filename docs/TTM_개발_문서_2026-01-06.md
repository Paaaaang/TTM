## 3. 트러블 슈팅

### 문제 1: exercise_log 테이블 미생성
**증상:**
- 운동 기록 API 호출 시 "Table doesn't exist" 오류
- schema.sql에는 정의되어 있으나 실제 DB에 반영 안됨

**원인:**
- 초기 데이터베이스 설정 시 schema.sql 일부 실행 누락

**해결:**
```sql
-- create_exercise_table.sql 생성 및 실행
CREATE TABLE IF NOT EXISTS exercise_log (
  exercise_log_id INT PRIMARY KEY AUTO_INCREMENT,
  member_id INT NOT NULL,
  exercise_name VARCHAR(100) NOT NULL,
  exercise_duration INT NOT NULL COMMENT '분 단위',
  calories_burned INT NOT NULL,
  exercise_intensity VARCHAR(20),
  notes TEXT,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (member_id) REFERENCES members(member_id) ON DELETE CASCADE
);
```

### 문제 2: 배지 데이터 미존재
**증상:**
- 배지 API는 정상 작동하지만 반환 데이터 없음
- 프로필 화면에서 빈 배지 목록 표시

**원인:**
- badge 테이블과 member_badge 테이블에 초기 데이터 미입력

**해결:**
```python
# create_badge_data.py 실행
# - 20개 배지 마스터 데이터 생성
# - admin, test 계정에 각 8개 배지 자동 수여
# 결과: "✅ 20개의 배지가 생성되었습니다! ✅ 2개 계정에 8개 배지 수여 완료!"
```

### 문제 3: 비밀번호 해싱 불일치
**증상:**
- 테스트 계정 로그인 실패
- admin 계정은 정상 로그인

**근본 원인:**
- **passlib 버전 차이**로 인한 bcrypt 호환성 문제
- 초기 설치 시와 재설치 시 passlib 버전이 달라 해싱 알고리즘이 변경됨
- 기존 DB의 해시값과 새 버전으로 생성한 해시값의 형식 불일치

**상세 원인:**
- 일부 계정의 비밀번호가 bcrypt 해싱 없이 평문 저장됨
- 회원가입 API는 정상 해싱, 직접 INSERT는 평문 입력
- 또는 passlib 버전 업데이트 후 verify() 메서드가 기존 해시 인식 실패

**해결:**
```python
# 1. passlib 버전 고정
pip install passlib[bcrypt]==1.7.4

# 2. check_password.py로 비밀번호 상태 확인
# bcrypt 해시로 통일: $2b$로 시작하는 60자 문자열

# 3. 모든 테스트 계정 비밀번호를 Test1234!@로 통일 및 재해싱
```

**교훈:**
- requirements.txt에 명확한 버전 명시 필수 (`passlib[bcrypt]==1.7.4`)
- 암호화 관련 라이브러리는 버전 변경 시 하위 호환성 깨질 수 있음
- 개발팀 전체가 동일한 requirements.txt 사용해야 함

### 문제 4: CORS 오류
**증상:**
- Flutter 웹 앱에서 API 호출 시 CORS 정책 위반

**해결:**
```python
# backend/main.py
from fastapi.middleware.cors import CORSMiddleware

app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],  # 개발 환경에서는 모든 origin 허용
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)
```

**test (member_id=2)**
- 식단 기록: 1개 (점심 - 샐러드, 닭가슴살, 방울토마토)
- 운동 기록: 2개 (런닝 40분, 요가 30분)
- 커뮤니티 게시물: 1개 (건강한 점심 식단)
- 보유 배지: 8개

### 테이블별 상세 구조

#### 6.1 members
```sql
CREATE TABLE members (
  member_id INT PRIMARY KEY AUTO_INCREMENT,
  email VARCHAR(100) NOT NULL UNIQUE,
  password VARCHAR(255) NOT NULL,
  name VARCHAR(50) NOT NULL,
  nickname VARCHAR(50),
  age INT,
  gender VARCHAR(10),
  height DECIMAL(5,2),
  weight DECIMAL(5,2),
  profile_image_path VARCHAR(255),
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);
```
**용도:** 회원 가입, 로그인, 프로필 관리  
**연결 파일:** `auth_provider.dart`, `profile_screen.dart`

#### 6.2 meal_log & meal_item
```sql
CREATE TABLE meal_log (
  meal_log_id INT PRIMARY KEY AUTO_INCREMENT,
  member_id INT NOT NULL,
  meal_date DATE NOT NULL,
  meal_type VARCHAR(20) NOT NULL COMMENT '아침/점심/저녁/간식',
  total_calories INT,
  notes TEXT,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (member_id) REFERENCES members(member_id) ON DELETE CASCADE
);

CREATE TABLE meal_item (
  meal_item_id INT PRIMARY KEY AUTO_INCREMENT,
  meal_log_id INT NOT NULL,
  food_name VARCHAR(100) NOT NULL,
  quantity DECIMAL(10,2),
  unit VARCHAR(20) COMMENT 'g, ml, 개 등',
  calories INT,
  protein DECIMAL(5,2),
  carbs DECIMAL(5,2),
  fat DECIMAL(5,2),
  FOREIGN KEY (meal_log_id) REFERENCES meal_log(meal_log_id) ON DELETE CASCADE
);
```
**관계:** 1:N (meal_log 1개 : meal_item N개)  
**용도:** 식단 기록 및 영양 정보 관리  
**연결 파일:** `meal_service.dart`, `home_screen.dart`, `meal_add_screen.dart`

#### 6.3 exercise_log
```sql
CREATE TABLE exercise_log (
```

#### 6.4 post & post_image
```sql
CREATE TABLE post (
  post_id INT PRIMARY KEY AUTO_INCREMENT,
  member_id INT NOT NULL,
  title VARCHAR(200) NOT NULL,
  content TEXT NOT NULL,
  view_count INT DEFAULT 0,
  like_count INT DEFAULT 0,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  FOREIGN KEY (member_id) REFERENCES members(member_id) ON DELETE CASCADE
);

CREATE TABLE post_image (
  post_image_id INT PRIMARY KEY AUTO_INCREMENT,
  post_id INT NOT NULL,
  image_path VARCHAR(255) NOT NULL,
  image_order INT DEFAULT 0,
  FOREIGN KEY (post_id) REFERENCES post(post_id) ON DELETE CASCADE
);
```
**관계:** 1:N (post 1개 : post_image N개)  
**용도:** 커뮤니티 게시물 및 이미지 관리  
**연결 파일:** `post_service.dart`, `community_home_screen.dart`, `create_post_screen.dart`

#### 6.5 badge & member_badge
```sql
CREATE TABLE badge (
  badge_id INT PRIMARY KEY AUTO_INCREMENT,
  badge_name VARCHAR(100) NOT NULL,
  description TEXT,
  icon_path VARCHAR(255),
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE member_badge (
  member_badge_id INT PRIMARY KEY AUTO_INCREMENT,
  member_id INT NOT NULL,
  badge_id INT NOT NULL,
  acquired_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (member_id) REFERENCES members(member_id) ON DELETE CASCADE,
  FOREIGN KEY (badge_id) REFERENCES badge(badge_id) ON DELETE CASCADE

```
**관계:** M:N (members ↔ badge, 중간 테이블 member_badge)  
**용도:** 배지 마스터 데이터 및 회원 획득 배지 추적  
**연결 파일:** `badge_service.dart`, `profile_screen.dart`  
**데이터:** 20개 배지 생성 완료 (🏃 피트니스 러너, 🌅 얼리버드 등)

## 7. 질문 사항 정리

### Q1: DateTime vs TIMESTAMP 차이?
**질문 배경:** meal_log, exercise_log 테이블의 created_at 컬럼 타입 선택

**답변:**
```sql
-- MySQL 데이터 타입 비교
DATETIME:
- 범위: '1000-01-01 00:00:00' ~ '9999-12-31 23:59:59'
- 저장: 8 bytes
- 타임존: 무관 (입력한 그대로 저장)
- 사용 예: 생일, 예약 시간 등 절대 시간

TIMESTAMP:
- 범위: '1970-01-01 00:00:01' UTC ~ '2038-01-19 03:14:07' UTC
- 저장: 4 bytes
- 타임존: UTC 기준 자동 변환
- 사용 예: created_at, updated_at 등 시스템 시간

선택: TIMESTAMP
이유: 1) 자동 타임존 변환 2) 작은 용량 3) 2038년까지 충분
```

**Dart에서 변환:**
```dart
// API 응답: "2026-01-06T10:30:00.000Z"
DateTime createdAt = DateTime.parse(json['created_at']);

// DB 저장용 변환
String toIso = createdAt.toIso8601String();  // "2026-01-06T10:30:00.000Z"
```

### Q2: 캐싱이 왜 필요한가?
**질문 배경:** 모든 서비스에 1시간 TTL 캐싱 구현

**답변:**
```dart
// 캐싱 없이 매번 API 호출
List<Badge> badges = await badgeService.getAllBadges();  // 300ms
List<Badge> badges2 = await badgeService.getAllBadges(); // 300ms
// 총 600ms

// 캐싱 적용
List<Badge> badges = await badgeService.getAllBadges();  // 300ms (첫 호출)
List<Badge> badges2 = await badgeService.getAllBadges(); // 1ms (캐시)
// 총 301ms
```

**효과:**
- 네트워크 요청 감소 → 속도 향상
- 서버 부하 감소
- 오프라인 대응 (캐시 데이터 활용)

**주의:**
- 데이터 변경(POST, PUT, DELETE) 시 캐시 무효화 필수
- TTL 너무 길면 최신 데이터 반영 지연

### Q3: 왜 snake_case와 PascalCase를 섞어 쓰나?
**질문 배경:** DB는 snake_case, Dart는 PascalCase

**답변:**
```
규칙:
- DB (SQL): snake_case (member_id, created_at)
- Backend (Python): snake_case (member_id, created_at)
- Frontend (Dart): PascalCase (memberId, createdAt)

이유:
- 각 언어/플랫폼의 표준 컨벤션 준수
- 코드 가독성 및 유지보수성 향상
- 자동 변환 로직으로 개발자 부담 감소
```

자세한 내용은 [9. 명명 규칙 및 매핑](#9-명명-규칙-및-매핑) 참고

### Q4: 비밀번호는 어떻게 안전하게 저장?
**질문 배경:** 회원 가입 시 비밀번호 처리 방법

**답변:**
```python
# ❌ 절대 금지: 평문 저장
INSERT INTO members (password) VALUES ('Test1234!@');

# ✅ 올바른 방법: bcrypt 해싱
from passlib.context import CryptContext
pwd_context = CryptContext(schemes=["bcrypt"], deprecated="auto")

hashed = pwd_context.hash("Test1234!@")
# 결과: $2b$12$randomSaltHere...
# 같은 비밀번호도 매번 다른 해시값 생성 (salt 때문)

# 로그인 시 검증
is_correct = pwd_context.verify("Test1234!@", hashed)  # True
```

**왜 bcrypt?**
- 해독 불가능 (일방향 암호화)
- 레인보우 테이블 공격 방어 (salt 사용)
- 느린 연산 속도 → 무차별 대입 공격 어려움

### Q5: JWT 토큰은 어디에 저장?
**질문 배경:** 로그인 후 토큰 관리 방법

**답변:**
```dart
// 안전한 방법: flutter_secure_storage
import 'package:flutter_secure_storage/flutter_secure_storage.dart';

final storage = FlutterSecureStorage();
await storage.write(key: 'auth_token', value: token);

// 위험한 방법: SharedPreferences (평문 저장)
SharedPreferences prefs = await SharedPreferences.getInstance();
prefs.setString('auth_token', token);  // 암호화 없음
```

**flutter_secure_storage 특징:**
- Android: Keystore 사용
- iOS: Keychain 사용
- 운영체제 수준 암호화

## 9. 명명 규칙 및 매핑

### 컨벤션 차이 이해

#### 9.1 각 계층별 명명 규칙

| 계층 | 컨벤션 | 예시 | 설명 |
|------|--------|------|------|
| **Database (SQL)** | `snake_case` | `member_id`, `created_at`, `meal_log_id` | MySQL 테이블/컬럼명 |
| **Backend (Python)** | `snake_case` | `member_id`, `get_member_by_id()` | FastAPI 변수/함수명 |
| **Frontend (Dart)** | `camelCase` | `memberId`, `getMeals()` | Dart 변수/메서드명 |
| **API Endpoint** | `kebab-case` | `/api/meal-logs`, `/api/exercises` | RESTful URL 경로 |
| **클래스명** | `PascalCase` | `MealService`, `ExerciseLog` | Dart/Python 클래스 |
| **파일명** | `snake_case` | `meal_service.dart`, `auth.py` | 소스 파일명 |
| **상수명** | `SCREAMING_SNAKE_CASE` | `API_BASE_URL`, `MAX_RETRY_COUNT` | 전역 상수 |
| **Private 변수** | `_camelCase` | `_cachedData`, `_updateCache()` | Dart private 멤버 |

#### 9.2 자동 변환 예시

**DB → Backend (Python)**
```python
# 변환 불필요 (둘 다 snake_case)
# MySQL
SELECT member_id, created_at FROM members;

# FastAPI
member_id = result[0]['member_id']
created_at = result[0]['created_at']
```

**Backend → Frontend (Dart)**
```dart
// API 응답 (JSON)
{
  "member_id": 1,
  "meal_log_id": 10,
  "created_at": "2026-01-06T10:30:00.000Z"
}

// Dart 모델 자동 변환
class Meal {
  final int memberId;        // member_id 매핑
  final int mealLogId;       // meal_log_id 매핑
  final DateTime createdAt;  // created_at 매핑

  factory Meal.fromJson(Map<String, dynamic> json) {
    return Meal(
      memberId: json['member_id'],      // snake_case로 접근
      mealLogId: json['meal_log_id'],
      createdAt: DateTime.parse(json['created_at']),
    );
  }

  Map<String, dynamic> toJson() {
    return {
      'member_id': memberId,            // 다시 snake_case로 변환
      'meal_log_id': mealLogId,
      'created_at': createdAt.toIso8601String(),
    };
  }
}
```

#### 9.3 단순 필드 매핑

```
───────────────────────────────────
member_id         →  memberId
meal_log_id       →  mealLogId
exercise_log_id   →  exerciseLogId
```

#### 9.4 복합 필드 매핑
```dart
// 중첩 객체 매핑
// Backend JSON
{
  "meal_log_id": 1,
  "meal_items": [
    {
      "meal_item_id": 1,
      "food_name": "김치찌개",
      "calories": 350
    }
  ]
}

// Dart 모델

}

class MealItem {
```

#### 문서화 주석 규칙
1. **클래스/함수 설명**: `///`로 시작하는 여러 줄 사용
2. **파라미터 설명**: `[parameterName]` 형식으로 표시
3. **반환값 설명**: "반환:", "Returns:" 등으로 명시
4. **예제 코드**: 마크다운 코드 블록 사용 가능

#### VS Code에서 확인하기
- 함수/클래스에 마우스 오버 시 문서화 주석이 툴팁으로 표시됨
- `Ctrl + Space` (자동완성) 시 문서 내용 표시
- `///`로 작성한 주석만 API 문서에 포함됨
