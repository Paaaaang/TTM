# TTM 프로젝트 디렉토리 구조

## 📁 프로젝트 구조 개요

```
lib/
├── main.dart                 # 앱 진입점
├── models/                   # 데이터 모델
├── screens/                  # 화면(페이지)
├── widgets/                  # 재사용 가능한 커스텀 위젯
├── services/                 # 비즈니스 로직 & API 서비스
├── providers/                # 상태 관리
├── utils/                    # 유틸리티 함수
├── constants/                # 상수 정의
└── routes/                   # 라우팅 관리
```

## 📂 디렉토리 상세 설명

### 1. **models/** - 데이터 모델
- 데이터베이스 테이블과 매핑되는 클래스
- API 응답 데이터 구조
- 앱 내부 데이터 구조 정의
- **예시**: `user_model.dart`, `product_model.dart`

### 2. **screens/** - 화면(페이지)
- 각 화면 단위의 UI 페이지
- 화면별 레이아웃 및 로직 구현
- 화면설계서의 각 페이지에 해당
- **예시**: `home_screen.dart`, `login_screen.dart`, `profile_screen.dart`

### 3. **widgets/** - 재사용 가능한 위젯
- 여러 화면에서 공통으로 사용되는 UI 컴포넌트
- 커스텀 버튼, 카드, 입력 필드 등
- **예시**: `custom_button.dart`, `custom_card.dart`, `loading_widget.dart`

### 4. **services/** - 비즈니스 로직 & 서비스
- API 통신 로직
- 데이터베이스 연동 서비스
- 인증/인가 처리
- 로컬 저장소 관리
- **예시**: `api_service.dart`, `auth_service.dart`, `database_service.dart`

### 5. **providers/** - 상태 관리
- Provider, Riverpod, Bloc 등 상태 관리 클래스
- 앱 전역 상태 관리
- 화면 간 데이터 공유
- **예시**: `user_provider.dart`, `theme_provider.dart`, `cart_provider.dart`

### 6. **utils/** - 유틸리티
- 공통 유틸리티 함수
- 날짜/시간 포맷팅
- 데이터 변환 헬퍼
- 유효성 검사
- **예시**: `date_utils.dart`, `validators.dart`, `formatters.dart`

### 7. **constants/** - 상수
- API URL 및 엔드포인트
- 색상 테마
- 문자열 상수
- 앱 설정값
- **예시**: `api_constants.dart`, `app_colors.dart`, `app_strings.dart`

### 8. **routes/** - 라우팅
- 화면 전환 경로 정의
- 라우트 이름 관리
- 네비게이션 로직
- **예시**: `app_routes.dart`, `route_generator.dart`

## 🎯 개발 가이드라인

### 명명 규칙
- 파일명: `snake_case.dart` (예: `user_profile_screen.dart`)
- 클래스명: `PascalCase` (예: `UserProfileScreen`)
- 변수/함수명: `camelCase` (예: `getUserData()`)

### 파일 구성 원칙
1. **단일 책임 원칙**: 각 파일은 하나의 명확한 목적을 가져야 합니다
2. **관심사 분리**: UI(screens/widgets), 로직(services), 데이터(models)를 명확히 분리
3. **재사용성**: 공통 기능은 widgets나 utils로 추출

### 개발 순서 권장사항
1. **constants** - 앱 전역 상수 정의
2. **models** - 데이터베이스 테이블명세서 기반 모델 생성
3. **services** - API 및 데이터베이스 서비스 구현
4. **widgets** - 공통 UI 컴포넌트 제작
5. **screens** - 화면설계서 기반 화면 구현
6. **providers** - 필요한 상태 관리 구현
7. **routes** - 화면 간 네비게이션 설정
